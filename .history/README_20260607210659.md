# Course Enrollment System API

**Version:** 2.0.0 | **Framework:** FastAPI | **Database:** PostgreSQL | **Auth:** JWT (HS256)

A RESTful API for managing a school enrollment system. It handles three core domains — **Users**, **Courses**, and **Enrollments** — with two distinct roles: `admin` and `student`. Built with a clean layered architecture: Routers → Services → Repositories → Database.

## Architecture

The app follows a strict 4-layer separation of concerns:

```
HTTP Request
     │
  Router          (routers/)       — Defines HTTP methods, paths, and response models
     │
  Service         (services/)      — Enforces business rules, validation, and error handling
     │
  Repository      (repository/)    — Contains ORM models and all direct database queries
     │
  Database        (core/db.py)     — Manages SQLAlchemy engine, sessions, and table creation
```

Each layer only talks to the layer directly below it. Routers never touch the database directly, and repositories contain no business logic.

## Database Models

### User (`users` table)

| Column            | Type    | Constraints              | Notes                          |
|-------------------|---------|--------------------------|--------------------------------|
| `id`              | Integer | PK, indexed              | Auto-increment                 |
| `name`            | String  | NOT NULL                 |                                |
| `email`           | String  | UNIQUE, indexed, NOT NULL| Used for login                 |
| `hashed_password` | String  | NOT NULL                 | bcrypt hash; never returned    |
| `role`            | Enum    | NOT NULL, default=student| Values: `admin`, `student`     |
| `is_active`       | Boolean | NOT NULL, default=True   | Inactive accounts are blocked  |

**Relationships:** One user → many enrollments (cascade delete-orphan)

---

### Course (`courses` table)

| Column      | Type    | Constraints              | Notes                          |
|-------------|---------|--------------------------|--------------------------------|
| `id`        | Integer | PK, indexed              | Auto-increment                 |
| `title`     | String  | NOT NULL                 |                                |
| `code`      | String  | UNIQUE, indexed, NOT NULL| e.g. `PY101`                   |
| `capacity`  | Integer | NOT NULL                 | Must be > 0                    |
| `is_active` | Boolean | NOT NULL, default=True   | Inactive courses block enroll  |

**Relationships:** One course → many enrollments (cascade delete-orphan)

---

### Enrollment (`enrollments` table)

| Column       | Type     | Constraints        | Notes                              |
|--------------|----------|--------------------|-------------------------------------|
| `id`         | Integer  | PK, indexed        | Auto-increment                      |
| `user_id`    | Integer  | FK → users.id      | The enrolling student               |
| `course_id`  | Integer  | FK → courses.id    | The course being enrolled in        |
| `created_at` | DateTime | NOT NULL, auto-set | Timezone-aware, set by DB on insert |

**Relationships:** Many-to-one back to both `User` and `Course`.

## Authentication & Authorization

### How It Works

The API uses **JWT Bearer tokens** signed with **HS256**. Tokens carry the user's `id` and `role` in the payload and expire after **30 minutes**.

**Authentication Flow:**
1. Call `POST /users/register` to create an account.
2. Call `POST /users/login` with your email and password.
3. You receive `{ "access_token": "...", "token_type": "bearer" }`.
4. Pass the token in the `Authorization` header on protected routes:
   ```
   Authorization: Bearer <your_token>
   ```

### Role Guards (`services/deps.py`)

Three dependency functions protect routes:

| Dependency         | Who it allows          | Error on failure       |
|--------------------|------------------------|------------------------|
| `get_current_user` | Any valid, active user | `401 Unauthorized`     |
| `require_admin`    | Admin role only        | `403 Forbidden`        |
| `require_student`  | Student role only      | `403 Forbidden`        |

Inactive accounts are rejected by `get_current_user` even with a valid token.

## API Reference

### Users — `/users`

#### `POST /users/register`
Register a new user. No auth required.

**Request body:**
```json
{
  "name": "Jane Doe",
  "email": "jane@example.com",
  "password": "securepassword",
  "role": "student"
}
```
- `role` defaults to `"student"` if omitted. Accepted values: `"student"`, `"administrator"`.

**Response `201`:**
```json
{
  "id": 3,
  "name": "Jane Doe",
  "role": "student",
  "is_active": true
}
```

**Errors:** `400` if email is already registered.

---

#### `POST /users/login`
Authenticate and receive a JWT token. No auth required.

**Request body:**
```json
{
  "email": "jane@example.com",
  "password": "securepassword"
}
```

**Response `200`:**
```json
{
  "access_token": "<jwt_token>",
  "token_type": "bearer"
}
```

**Errors:** `401` for invalid credentials, `403` if account is inactive.

---

#### `GET /users/me`
Returns the currently authenticated user's profile. Requires a valid JWT.

**Response `200`:**
```json
{
  "id": 3,
  "name": "Jane Doe",
  "role": "student",
  "is_active": true
}
```

---

### Courses — `/courses`

#### `GET /courses/`
Returns all **active** courses. No auth required.

**Response `200`:** Array of course objects.

---

#### `GET /courses/{course_id}`
Returns a single course by ID. No auth required.

**Errors:** `404` if course not found.

---

#### `POST /courses/` *(Admin only)*
Creates a new course.

**Request body:**
```json
{
  "title": "Introduction to Python",
  "code": "PY101",
  "capacity": 30
}
```

**Response `201`:** The created course object.  
**Errors:** `400` if course code already exists.

---

#### `PATCH /courses/{course_id}` *(Admin only)*
Partially updates a course. All fields are optional.

**Request body (any subset):**
```json
{
  "title": "Advanced Python",
  "capacity": 50,
  "is_active": false
}
```

**Errors:** `404` if course not found, `400` if the new code conflicts with an existing one.

---

#### `DELETE /courses/{course_id}` *(Admin only)*
Permanently deletes a course and all its enrollments (cascade).

**Response `200`:** `{ "detail": "Course deleted successfully" }`  
**Errors:** `404` if course not found.

---

### Enrollments — `/enrollments`

#### `GET /enrollments/me` *(Student only)*
Returns all enrollments belonging to the currently authenticated student.

---

#### `GET /enrollments/` *(Admin only)*
Returns all enrollments across the entire system.

---

#### `GET /enrollments/course/{course_id}` *(Admin only)*
Returns all enrollments for a specific course.

**Errors:** `404` if course not found.

---

#### `POST /enrollments/` *(Student only)*
Enrolls the current student in a course.

**Request body:**
```json
{
  "course_id": 3
}
```

**Response `201`:**
```json
{
  "id": 7,
  "user_id": 3,
  "course_id": 3,
  "created_at": "2026-06-07T19:14:00Z"
}
```

**Errors:**
| Code | Reason                             |
|------|------------------------------------|
| `404`| Course not found                   |
| `400`| Course is inactive                 |
| `400`| Already enrolled in this course    |
| `400`| Course is at full capacity         |

---

#### `DELETE /enrollments/{enrollment_id}` *(Student only)*
Allows a student to deregister from one of their own enrollments.

**Errors:** `404` if enrollment not found, `403` if the enrollment belongs to a different student.

---

#### `DELETE /enrollments/admin/{enrollment_id}` *(Admin only)*
Force-removes any enrollment regardless of ownership.

**Errors:** `404` if enrollment not found.

## Business Logic

### UserService
- Passwords are hashed with **bcrypt** before being stored; plaintext is never persisted.
- Duplicate email check happens at registration time.
- On login, bcrypt comparison is used against the stored hash.
- Both login and every authenticated request check `is_active`; inactive users are always blocked.

### CourseService
- Course codes are enforced as globally unique, both on create and when updating the code field.
- `delete` is a hard delete — the record is removed from the DB, and SQLAlchemy cascades the deletion to all related enrollments.

### EnrollmentService
Four sequential checks run before an enrollment is created:
1. **Course exists** — `404` if not.
2. **Course is active** — `400` if not.
3. **No duplicate** — `400` if the student is already enrolled.
4. **Capacity check** — `400` if enrollment count ≥ course capacity.

On student deregister, ownership is verified against `enrollment.user_id`. Admin remove skips this check entirely.

## Notes & Gotchas

- **`.env` is committed** in this exam project. For any real deployment, add it to `.gitignore` and use a secrets manager or environment injection instead.
- **`SECRET_KEY`** should be a cryptographically random string (e.g. `openssl rand -hex 32`) in production.
- **SQLite compatibility shim:** `core/db.py` includes `check_same_thread: False` when the DB URL contains `sqlite`. This is used to support an in-memory SQLite DB during testing without changing any other code.
- **Token expiry** (30 minutes) is hardcoded in `services/user.py`. Consider moving it to `.env` as `ACCESS_TOKEN_EXPIRE_MINUTES` for easier configuration.
- The schema uses `UserRole.ADMIN = "administrator"` in the Pydantic schema but `UserRole.ADMIN = "admin"` in the SQLAlchemy model. These are separate enums — be aware of this distinction if you're constructing tokens or queries manually.
